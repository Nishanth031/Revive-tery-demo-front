# REVIVE-TERY

A battery second-life toolkit: monitor a battery on the bench, estimate its state of charge and health,
and decide whether it can be reused, repurposed or should be recycled.

It runs entirely on your own machine and has three parts:

| Part | Folder | What it is |
|---|---|---|
| **Circuit Studio** | `src/` | A single-page Dash dashboard: the test circuit, live readings, SOC/SOH, end-of-life decision, and an ML analyzer panel for uploaded battery data |
| **Backend API** | `backend/` | A local FastAPI service in front of the database, the BMS engine, test runs and the ML engine (see [backend/README.md](backend/README.md)) |
| **Firmware** | `firmware/revive_tery_esp32/` | ESP32 sketch that reads voltage/current (INA219) and temperature (DS18B20) and prints one JSON line per second over USB |

```
 ESP32 (INA219 + DS18B20) ──USB serial, read-only──▶  bms_engine.py ──▶ run_controller.py
                                                              │                 │
          software ESP32 (esp32_sim.py) ─────────────────────┘                 ├──▶ Circuit Studio (Dash, :8050)
          virtual replay of recorded telemetry ─────────────────────────────────┤
                                                                                └──▶ Backend API (FastAPI, :8000)
                                                   DuckDB (data/database/revive_tery.duckdb)
```

## Test modes

- **Virtual replay**: plays back telemetry already in the database.
- **Simulated ESP32**: a software ESP32 and circuit, with fault injection. No hardware needed.
- **Real ESP32**: reads the firmware's JSON lines from a serial port.

Hardware access is **monitor-only**. The software never writes to the ESP32, and the firmware drives no outputs.

## Quick start

Requires Python 3.13 (the optional ML engine is built and tested on it).

```powershell
py -3.13 -m venv .venv-studio
.venv-studio\Scripts\python.exe -m pip install -r src\requirements.txt

# Build the DuckDB database from the CSV bundle in data/csv_bundle (the .duckdb file is not in git)
.venv-studio\Scripts\python.exe src\build_relational_db.py

# Start Circuit Studio, then open http://127.0.0.1:8050
.venv-studio\Scripts\python.exe src\app.py
```

To run the backend API instead, follow [backend/README.md](backend/README.md). DuckDB allows one writer,
so close Circuit Studio before starting the API.

### Optional: full ML engine

The ML panel uses a built-in lite analyzer by default. For the full engine (data-quality checks, safety gate,
remaining-life prediction with intervals, economics), install `revive-tery-ml` from its own folder:

```powershell
.venv-studio\Scripts\python.exe -m pip install -e ..\revive-tery-ml
```

## Data

- `data/csv_bundle/`: the demo dataset (battery assets, modules, telemetry, health history, charge sessions,
  safety events, recycling materials) used to build the database.
- `data/ml_samples/`: **synthetic** sample uploads for the ML panel, generated by `src/make_ml_samples.py`.

## Hardware safety

The firmware is for **low-voltage bench use only**. The INA219 is rated to 26 V, so never connect it to an EV pack.
The setup provides no protection: your battery and load need their own fuse and protection.
Wiring is listed at the top of the `.ino` file and shown in Circuit Studio.

## Tests

The backend has a pytest suite. Run it from `backend/` in the backend's environment, as described in
[backend/README.md](backend/README.md). Tests run against a scratch copy of the database, never the project file.
