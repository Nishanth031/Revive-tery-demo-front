# revive-tery-ml

Standalone ML engine for **REVIVE-TERY**, an EV-battery second-life decision-support project.
It answers two questions, in this order:

1. **Can this battery's data be trusted?** 14 data-quality checks, each pass / warn / fail /
   inconclusive with evidence, combined into a readiness verdict by explicit rules. If the data
   fail, the report says **"Insufficient or untrustworthy data"** and makes no recommendation.
2. **If so, what should happen to it?** A safety triage gate (Reject / Quarantine / Pass), a
   measured or modelled state estimate with an interval, physics projections for chosen
   workloads with two separate uncertainty bands, and an economics router (Second-Life with a
   specific application, or Recycle, benchmarked against Buy New). A Quarantine verdict gives
   **"Inspection required"**, not a recommendation.

Every number in a report carries a provenance tag: `measured`, `modelled`, `assumed` or
`synthetic`. **All REVIVE-TERY project data is synthetic.** Results on it show that the pipeline
works, not anything about a real battery.

The engine is independent of the other REVIVE-TERY code. It imports nothing from Circuit Studio,
`bms_engine.py`, `test_bench.py`, `esp32_sim.py`, ReLife BMS Studio, the firmware, or any
serial/MQTT code. The only coupling is the file contract below.

## Quick start (Windows, Python 3.13)

```bash
py -3.13 -m venv .venv
```
```bash
.venv/Scripts/python.exe -m pip install -e ".[dev,api]"
```
```bash
.venv/Scripts/just.exe demo
```

`just demo` converts the demo CSV bundle, then assesses it and a clean synthetic bundle:

```bash
.venv/Scripts/revive-ml.exe assess examples/demo_bundle --out out/demo_report.json
```
```bash
.venv/Scripts/revive-ml.exe assess examples/clean_synthetic_bundle --out out/clean_report.json
```

- `demo_bundle` (the REVIVE-TERY demo pack, NMC, synthetic) gives **Insufficient or untrustworthy
  data**: SOC falls 34 points while the recorded current explains 17.1, the one regenerative-braking
  row has the driving current sign, and live SOH (about 50 %) disagrees with the capacity test
  (96.8 %). The 2.2 mOhm pack resistance is reported **inconclusive** (0.92 mOhm per cell is
  implausible for 21700 cells).
- `clean_synthetic_bundle` (generated by `revive_ml.synth`, LFP, labelled synthetic) runs every
  stage and ends in a recommendation that depends on PLACEHOLDER cost inputs.

## Data contract

A bundle is a directory:

| File | Content |
|---|---|
| `metadata.json` | `asset_id`, `chemistry` (LFP/NMC/NCA), `rated_capacity_ah`, `nominal_voltage_v`, `min_voltage_v`, `max_voltage_v`, `series_cells`, `parallel_cells`, `data_provenance` (measured/simulated/synthetic), `current_sign_convention` (discharge_negative/discharge_positive/unknown), optional `capacity_tests`, `resistance_tests`, `safety_events`, `cycle_count` (each record carries its own provenance) |
| `telemetry.parquet` or `telemetry.csv` | required `asset_id`, `timestamp_utc` (ISO-8601 UTC), `voltage_v`, `current_a`, `temperature_c`; optional `soc_pct`, `min_temperature_c`, `ambient_temperature_c`, `power_kw`, `operating_state`, `bms_soh_pct` |

Schemas are enforced with pydantic (metadata) and pandera (telemetry). A missing or misnamed
column fails loudly (exit code 2) and names the likely culprit, e.g. `'pack_voltage_V' looks like
'voltage_v'`. Columns are never renamed by guessing; `revive-ml convert-demo` applies the explicit
mapping documented in [PLAN.md](PLAN.md).

## Pipeline

| Stage | Module | Output |
|---|---|---|
| Data quality | `dq/detectors.py`, `dq/readiness.py` | 14 checks + verdict READY / READY_WITH_WARNINGS / NOT_READY |
| Safety gate | `gate/limits.py`, `gate/ood.py` | Reject (datasheet limits) / Quarantine (IsolationForest OOD + envelope, open HIGH events) / Pass |
| State | `state/estimate.py`, `state/train.py` | SOH from the latest capacity test; remaining cycles at reference conditions with a CV+ interval |
| Projection | `physics/fade.py` | SOH per year for each workload: central path, ML band, Monte Carlo band, knee scenario |
| Economics | `econ/router.py` | Net value per second-life application vs recycling now; decision and rationale |

Readiness rules: any `fail` gives NOT_READY; otherwise any `warn` or `inconclusive` gives
READY_WITH_WARNINGS; otherwise READY. An `inconclusive` quantity is excluded from the decision.

| Target | What it does | Output |

| `test` / `lint` | pytest / ruff | |

| `train-gate` | OOD filters, grouped CV | `models/gate_ood_*.joblib`, `reports/gate_validation.json` |

Seeds are fixed (0). The raw-data cache defaults to `%LOCALAPPDATA%\revive-tery-ml\cache`
(override with `REVIVE_ML_CACHE`) so gigabytes do not sync to OneDrive.

## Key results (all computed, see `reports/`)

| Item | Result |
|---|---|
| DQ detectors, 100 held-out synthetic bundles | 16 fault types: 15 detected 100/100, stuck voltage 99/100; 0 false positives on clean bundles |
| RUL, 128 Severson LFP cells, GroupKFold by cell (field features) | RMSE 385 (naive mean) -> 276 (ElasticNet) -> **169 cycles** (gradient boosting); MAPE 107 % -> 34 % -> **16.6 %** |
| RUL with lab-only dQ(V) features | RMSE 133 cycles, MAPE 14.3 % |
| CV+ 90 % interval, nested grouped CV | measured coverage **91.5 %**; 80.6 % for windows with > 700 cycles left |
| Existing SOH rule vs ML on "is >= 1 year left?" | rule: 52 % accuracy, 100 % false-go; ML lower bound: 84 % accuracy, 0.6 % false-go |
| Gate, measured NASA cells (12-fold by cell) | clean quarantine 0.2 %; dropout 60 %, spikes 2 %, drift ~0 % detected |
| Gate, synthetic packs (5-fold by seed) | clean quarantine 0 %; spikes 100 %, dropout 97 %, voltage drift 10 %, temperature drift 0 % |
| Physics sanity | 6/6 pass; 25 -> 45 degC life ratio 2.27 (Ea 31.7 kJ/mol), not the 4.0 of a 10 degC-doubling rule |

## Limitations

- **No real-battery validation.** Every REVIVE-TERY bundle is synthetic. Public datasets are
  single lab cells (Severson LFP, NASA 18650), not used EV packs.
- **Distribution shift.** The RUL model is trained on new LFP cells cycled to 80 % under fast-charge
  protocols at 30 degC. Second-life packs differ in chemistry, scale and duty, so the measured CV+
  coverage does not carry over. The report warns when inputs leave the training range or the
  chemistry differs (the NMC demo pack always triggers this).
- **Below 80 % SOH everything is projection.** The physics parameters are literature-informed
  assumptions (configs/physics.yaml), not fitted to any battery. The Monte Carlo band is
  assumption-conditional, not a measured interval.
- **Gate.** Limits act on the pack-average cell voltage, so a weak cell can be hidden. The
  IsolationForest is an out-of-distribution and sensor-noise screen, not a fault detector. It
  misses slow drift, and on NASA cells it misses moderate spikes. The pack OOD model is trained on
  synthetic packs, so it measures "unlike the simulator", not "unlike real healthy packs".
  "UL 1974-style triage" means screening only: no UL certification or safety approval is claimed.
- **Data-quality rates are optimistic.** The faults were injected by the same author who wrote
  the detectors, on synthetic data.
- **Economics.** The second-life energy value, refurbishment, testing, logistics and installation
  costs and the payable fractions are PLACEHOLDERs; metal and pack prices are indicative web-sourced
  values from 2026-11-03. Decisions near the break-even point can flip with them.
- **Datasets.** NASA "Recommissioned" was not downloaded (no direct file URL). CALCE CS2 cells were
  downloaded but not used. 128 Severson cells pass the documented cleaning rules vs 124 in the paper.
- **No GRU/LSTM** was tried (torch not installed; optional per the brief).
- Models are pickled with scikit-learn 1.9.1; retrain with `just train train-gate` after upgrading.

## API (optional)

`uvicorn revive_ml.api:app` exposes `POST /assess` (a JSON body with `metadata` and `telemetry`
rows) and `GET /health`. It is a thin wrapper over the same `assess()` function.
