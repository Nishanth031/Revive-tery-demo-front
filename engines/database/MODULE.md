# engines/database: DuckDB build scripts, demo tables, sample uploads

**Purpose:** build `data/db/revive_tery.duckdb` from `csv_bundle/` (8 tables: battery_asset, modules, charge_sessions, telemetry, health_history, safety_events, materials_recycling, data_sources); generate 7 synthetic upload samples.
**Runtime tables created by other modules:** `ml_telemetry`, `ml_ingest_log`, `test_run_log`, `assessments`.
**Rules:** DuckDB allows one writer: close Circuit Studio / API / ReLife before writing. Honour `REVIVE_DB`. The browser needs a storage-v1.0 copy (`apps/web-studio/tools/convert_db.py`) because DuckDB-WASM cannot open v2.0 files yet.
**Origin:** `bulid X/database/`, `bulid X/src/build_relational_db.py`, `make_ml_samples.py`.
**Run:** `just db`.

**Fleet (synthetic):** `make_demo_fleet.py` adds six made-up packs (002-007: healthy/worn NMC, two LFP, an end-of-life NMC, an NCA pack with a critical thermal event) to `csv_bundle/`, all labelled SYNTHETIC. `battery_asset` is now `(asset_id, field, value)`; every consumer filters on `asset_id` (`bms_engine.load_battery_profile`, `ml_engine_bridge.bundle_from_database`, `backend_connector`, ReLife `database.py`, and the JS ports `bms.js` / `contract.js`). After changing the CSVs: `python engines/database/make_demo_fleet.py`, `just db`, then refresh the web copy (export_assets `copy_files` + `tools/convert_db.py`).

## The fleet (since the upgrade, `just db`)

**Source:** the user's own 60-pack database, github.com/Nishanth031/revive-tery-DB (`revive_tery.duckdb`), read-only. `import_fleet.py` looks for it at `REVIVE_FLEET_SRC`, `../_import/revive-tery-DB/revive_tery.duckdb` or `data/import/revive_tery.duckdb`; without it the committed CSVs in `csv_bundle/` are used as they are.
**`just db` = `import_fleet.py`:** (1) refresh `csv_bundle/` from the user's database (its 60 `battery_registry` rows + the platform's key/value `battery_asset` generated from them; child tables with timestamps normalised to UTC; the user's packs win any id conflict, including their capacity histories); keeps the 4 platform-only packs (DEMO-EV-PACK-002/007, DEMO-LFP-PACK-004/005) as they are; adds 6 labelled test cases `DEMO-FLAW-01..06` (one injected data fault each: mid-record sign flip, 60-min gap, stuck voltage, temperature spikes, null voltage, capacity-test disagreement); (2) build the DB; (3) `telemetry_dense`; (4) views and runtime tables.

**`telemetry_dense` is SYNTHETIC.** 1,020 rows at 10 s per pack, `data_class = 'SYNTHETIC'`, `source` says how it was made. Generated per pack (seed = CRC32 of the asset_id) from the pack's registry spec (chemistry, `NsMp`, rated Ah, min/max V) and its latest capacity test (true capacity, pack resistance), with the engine's documented physics model (`revive_ml.synth`: chemistry OCV curve, drive/regen/charge current profile, coulomb-consistent SOC at the measured capacity, IR drop, lumped thermal model whose heat capacity AND cooling scale with pack capacity). Charging is CC-CV and discharge is derated at the pack's own voltage window (0.995 x max, 1.005 x min), as a real charger/BMS would. A recorded `CELL_TEMPERATURE_WARNING` event adds a smooth excursion to its observed value; voltage-imbalance and insulation events have no pack-telemetry signature and are not drawn. **The original 12-row `telemetry` is never changed**; it stays available (`telemetry_source = original`, shown on the pack page as "original sample"). The engine's data-quality rules were not changed.
**Switch:** `ml_engine_bridge.bundle_from_database(con, id, telemetry_source="dense"|"original")` (API: `AssessIn.telemetry_source`; JS: `convertDemo(tables, id, {telemetry})`). Default `dense` for assessments and the web fleet.
**Tables:** `battery_registry` (one row per pack, + `registry_source`: user fleet DB / platform demo fleet / platform test case) and everything above. **Views:** `fleet_summary` (one row per pack: chemistry, latest capacity-test SOH, cycles, open safety events, telemetry rows), `pack_history` (asset_id, assessment_date, cycle_count, soh_pct, resistance_mohm).
**Runtime tables** (created if missing; owners): `assessments` and `ml_suggestions` (API), `fleet_reports` (`fleet_reports.py`: asset_id, generated_utc, engine, telemetry_source, decision, disposition, soh_pct, rul_cycles, net_value_usd, confidence, registry_status, rule_agrees, rule_reason, report_json).
**Commands:** `just db` (rebuild), `just fleet` (assess every pack -> `fleet_reports`; compares the registry's SOH-threshold `lifecycle_status` with the engine via `config/decision_map.json` `registry_status_expectation`), `just web-db` (rebuild + fleet + web copy: DuckDB-WASM file, CSVs, `db_meta.json`, `history.json`), `just test-db` (`test_fleet.py`). Stop the API first: one writer.
